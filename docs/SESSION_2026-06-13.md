## 做了什么(按主题)

### A. 监督程序(最大块,北极星=人工省力比)
- 新增 `eval/` 包:`protocol.py`(无头复跑真实标注循环:Phase A 雪球 5类×25、
  Phase B 开集探针)、`effort.py`(省力比成本模型)、`report.py`(指标+门槛+回归对比)、

- 唯一入口 `scripts/supervise.py`(`--quick` / 全量 / `--compare` / `--sweep` /

- 协议文档 `eval/PROTOCOL.md`,首轮结论 `results/supervise/FINDINGS.md`。

  `conf_auto=0.68 / conf_suggest=0.55 / margin_auto=0.08`。**历史 env 0.85/0.75/0.61、
  0.60/0.58/0.41 全部作废,跑分/起服务都别带。**
- 特征空间指纹守卫(`features.feature_space_id`):换 模型/分辨率/分块/crop-pad,
  两后端加载非空旧库且指纹不符直接报错——保护,不是 bug。

### C. 前端交互与显示(labeler.html,详见 FRONTEND.md)
- Everything 模式:隐藏没认出的"?"碎块;点已识别 mask 改类;点空白补漏检并进入
  完整单点流程(多正点、右键负点、Space 收下一个、C 重跑全分割、Enter 入库)。
- 显示从半透明填充改为**服务器 cv2 轮廓 + 前端细线描边、绕质心外扩 10%**;

## 重要决策(一句话,详见 DECISIONS.md)

- **SAM 保持 tiny,不升 base**:base 的更精细 mask 反而把 truck 的特征推得比真 car
  还像 car(cw 0.783),越过 auto 阈值造成污染;没有任何余弦地板能分开真正易混的类。
  **监督程序正确抓住了这点**——这正是"真正好用而非数据好看"的体现。
- 512+parts4 的内存:每条约 68KB,demo 规模(~万条内)RAM 镜像不会顶爆。
